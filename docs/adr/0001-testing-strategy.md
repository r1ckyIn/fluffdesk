# ADR 0001：测试策略

状态：已采纳（2026-10-28）

## 背景

fluffdesk 的核心是一个调模型的 agent 循环。模型输出不确定，传统单测守不住它；
而行业经验是 agent 写的测试套件常常"永远全绿"（参考实现上 88% 通过，变异分数不到 60%）。
我们要的护栏是：改坏了会红，改对了不红，CI 里跑不花钱。

## 决定

测试分四层，各守各的，不互相替代：

1. **确定性单元测试**，只测纯业务规则：报价不超价目表、体重映射体型档、价目合并、HTML 转文本。
   这些是真规则，不是实现细节，常数变了测试就该变。
2. **契约测试**，守 CLAUDE.md 的规矩和工具边界：write 级工具进不了注册表、agent 只能产生 pending、
   报价文本必含免责声明、抓取遇到超时/404/非 HTML 不抛、参数校验失败回给模型而不是崩。
   每条对应一条规矩或一个外部边界，每次提交都跑。
3. **录制回放的 e2e**：eval 集用真模型跑一遍，每次模型回复按请求指纹录进 `packages/eval/recordings/`，
   CI 按指纹回放。指纹对不上（提示词、工具、输入变了）直接失败，强制重新录制。
   这样 e2e 用的是真实模型输出而不是手写脚本，又不花钱、确定。
4. **eval**，和测试分开，跑真模型，花钱：数据集 jsonl 版本化，先代码判分，模型评审只在代码判分全过后用，
   且要和人工打分对齐到 75% 以上才算数。用 pass^k（每条跑 k 次全过）衡量稳定性。
   改提示词、换模型、合并前跑；不是每次提交都跑。

另外两条纪律：

- **变异测试**：`scripts/mutate.sh` 固定一组"改坏核心逻辑"的变异，CI 里跑，逃掉一条就红。
  全绿只说明测试没报错，不说明有护栏；抓获率才说明。
- **真店回归**：改抽取或合并逻辑后，用 Fenny & Jacks 重跑导入，核对七个服务、六档价目、营业时间。

## 不做什么

- 不写测实现细节的单测（比如断言某个置信度常数等于 0.9）。常数是产品调参，不是规则。
- 不 mock 被测对象本身。faux 模型只用来喂输入，不用来替代被测的循环或工具。
- 不在 CI 里调真模型。真模型只在录制和 eval 时调，由人触发。
- 不锁工具调用顺序，除了"报价前必须调 quote"这一条关键顺序。其余评最终状态。

## 为什么不是别的

- 只写 e2e：出问题定位慢，而且护栏规矩（pending、免责声明）在 e2e 里是隐含的，改坏了未必红。
- 只写单测：模型行为测不到，agent 的问题大多出在循环和提示词上。
- 用第三方 eval 平台：源码、测试集、提示词要全在自己手里，可迁移。pi-ai 的 faux provider 和
  Context 序列化已经够做录制回放。

## 强制力

ADR 本身没有强制力，任何会话都不会自动读它。真正的约束在三处，强度递减：
CI 门禁（`.github/workflows/ci.yml`，不过不能合）、`CLAUDE.md`（每次会话加载）、README（命令）。
改这份 ADR 要同步改 CLAUDE.md 里对应的那几行。
